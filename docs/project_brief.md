# 의료 접근성이 지역 사망률에 미치는 영향 분석

> 전국 시군구 데이터를 활용한 회귀모델링 미니 프로젝트 · 팀원 3명

---

## 1. 한 줄 요약

**"의사가 많고 응급실이 가까운 지역일수록 사망률이 낮을까? 소득과 고령화의 영향을 빼고 봐도 그럴까?"**
전국 시군구(약 230개)의 공공데이터를 모아 회귀모델로 확인합니다.

## 2. 왜 이 주제인가

- 같은 나라 안에서도 사는 지역에 따라 제때 치료받을 가능성이 크게 다릅니다.
  - 2024년 인구 10만 명당 치료 가능 사망률: 충북 51.55명, 경북 50.20명, 서울 39.72명
  - 응급의학과 전문의가 한 명도 없는 시군구: 229곳 중 66곳
  - 응급의료 취약지로 지정된 시군구: 98곳 (2026년 기준)
- 의대 정원, 응급실 미수용, 지역 필수의료 문제로 사회적 논쟁이 큰 주제입니다.
- 의사가 적은 지역은 대체로 고령화되고 소득이 낮습니다. **단순 비교로는 의료 접근성의 효과인지, 고령화·소득의 효과인지 구분할 수 없습니다.** 이 둘을 분리해 보는 것이 이 프로젝트의 핵심입니다.

## 3. 분석 질문 (가설)

| 번호 | 질문 | 유형 |
|---|---|---|
| Q1 | 인구 1,000명당 의사 수가 많은 시군구일수록 연령표준화 사망률이 낮은가? | 관계 |
| Q2 | 소득, 고령인구 비율, 흡연율을 통제해도 그 관계가 유의하게 남는가? 효과는 얼마나 줄어드는가? | 통제 후 변화 |
| Q3 | 의사 수와 응급의료 취약지 여부 중 어느 쪽이 사망률을 더 잘 설명하는가? | 비교 |

(추가) 의사 수의 효과는 비선형일 수 있습니다. 의사가 적은 지역일수록 한 명이 늘 때의 효과가 클 수 있습니다.

## 6. 분석 흐름 (보고서 양식 순서)

1. **데이터 수집 (3장)**: 위 8종 데이터 확보
2. **전처리 (4장)**: 행정구역코드 통일 → 연령표준화 사망률 계산 → 하나의 테이블로 병합
3. **EDA (5장)**: 변수 분포, 시군구 지도 시각화, 상관분석, 취약지 vs 비취약지 비교
4. **모델링 (6장)**
   - 기준모델: 평균값 예측
   - 해석용: 다중선형회귀 (통제변수를 하나씩 추가하며 의사 수 계수 변화 확인 → Q2)
   - 비교용: 의사결정나무 또는 랜덤포레스트
   - 학습:평가 = 80:20
5. **평가 (7장)**: MAE, RMSE로 기준모델과 비교, 변수 중요도 해석
6. **결론 (8장)**: Q1~Q3에 답하기

## 7. 역할 분담

작업 단계별로 나눕니다. 팀장(일정 관리, 보고서 통합)은 셋 중 한 명이 겸합니다.

| 담당 | 주요 업무 | 보고서 담당 장 |
|---|---|---|
| **팀원 1 · 데이터 수집** | 8종 데이터 수집과 원본 보관, 출처·수집일·기준 연도 기록, 응급의료 취약지 고시 목록을 표로 정리, API 호출 코드 작성 | 3장, 4.1(원본 데이터 구성), 참고자료 및 부록 |
| **팀원 2 · 전처리 및 분석** | **행정구역코드 매핑 테이블** 작성, 결측·중복·이상치 처리, **연령표준화 사망률 계산**, 데이터 병합, EDA·시각화 (지도, 산점도, 상관행렬, 취약지 vs 비취약지 비교) | 4.2~4.4장, 5장 |
| **팀원 3 · 모델링 및 오류잡기** | 기준모델·회귀·트리 모델 구축, 성능 평가 (MAE, RMSE), **예측 오류 분석** (크게 틀린 시군구와 이유), **단계별 데이터 검증** (아래 체크리스트), 다중공선성(VIF) 확인 | 6장, 7장 |

**공동 작업**
- 1~2장(개요, 문제정의)은 초안이 있으니 셋이 읽고 함께 다듬기
- 8장(결론)은 모델 결과를 보고 셋이 함께 작성
- 팀원 역할 및 학습 소감은 각자 작성

### 오류잡기 체크리스트 (팀원 3)

다음 단계로 넘기기 전에 팀원 3이 확인하고, 문제가 있으면 해당 담당에게 돌려줍니다.

| 시점 | 확인할 것 |
|---|---|
| 수집 직후 | 파일마다 기준 연도가 맞는가? 시군구 개수는 몇 개인가? |
| 매핑 후 | 코드가 매칭되지 않은 시군구가 있는가? (0개여야 함) |
| 사망률 계산 후 | 전국 연령표준화 사망률이 KOSIS 공표값과 비슷한가? 값이 비정상적으로 크거나 작은 시군구는 없는가? |
| 병합 후 | 최종 행 수가 예상(약 230)과 맞는가? 결측이 남은 변수는 없는가? |
| 모델링 시 | 평가 데이터가 학습에 섞이지 않았는가? (표준화는 학습 데이터에만 fit) |

### 작업 순서와 의존 관계

```
[1] 데이터 수집 ──> [2] 매핑·전처리·병합 ──> [2] EDA ──> [3] 모델링·평가 ──> 보고서 통합
        │                  │                                    │
        └──── [3] 단계별 검증 ────┘──────────────────────────────┘
```

- **수집이 끝나야 다음 단계가 시작되므로, 팀원 1의 마감일을 가장 먼저 정하세요.** 결과변수용 데이터(사망자 수, 인구)를 먼저 넘기면 팀원 2가 사망률 계산을 일찍 시작할 수 있습니다.
- 기다리는 동안 팀원 2는 매핑 테이블과 사망률 계산 코드를 미리 만들고, 팀원 3은 모델링 코드 틀과 검증 코드를 준비합니다.
- 수집이 끝난 팀원 1은 참고자료·부록 정리와 보고서 통합을 돕습니다.

## 8. 협업 규칙

**공통 키**
- 모든 데이터는 `sigungu_code`(행정구역코드 5자리)와 `sigungu_name`(시군구명) 컬럼을 갖습니다.
- 시군구명으로 병합하지 않습니다. 이름은 출처마다 표기가 달라서(예: "수원시 영통구" vs "영통구") 반드시 코드로 합칩니다.

**폴더 구조** (저장소 구조 그대로 사용)
```
DeepLearningPJ/
├── data/
│   ├── raw/          # 원본 그대로 (절대 수정 금지, Git에는 올라가지 않음)
│   └── processed/    # 전처리 결과 (Git에는 올라가지 않음)
├── notebooks/        # 01_collect, 02_preprocess, 03_eda, 04_model ...
├── src/              # 노트북에서 반복해 쓰는 함수 (코드 매핑, 사망률 계산 등)
├── outputs/
│   ├── figures/      # 보고서용 그래프
│   └── models/       # 학습된 모델 (Git 제외)
└── docs/             # 보고서와 프로젝트 문서
```

- `data/`는 `.gitignore`로 제외돼 있습니다. 데이터 파일은 공유 드라이브로 주고받고, Git에는 **수집 코드와 출처 기록**만 올립니다. 그래야 누구나 같은 데이터를 다시 받을 수 있습니다.

**파일 이름 규칙**
- 원본: `raw/출처_내용_연도.csv` (예: `raw/kosis_deaths_2022_2024.csv`)
- 처리본: `processed/내용.csv` (예: `processed/merged_sigungu.csv`)

**주의사항**
- 출처마다 시군구 개수가 다릅니다 (226~258개). 행정구(일반구)를 따로 세는지, 보건소 기준인지 확인하세요.
- 대구 군위군(2023년 편입)처럼 경계가 바뀐 지역은 연도별로 코드를 확인하세요.
- API 키는 코드에 직접 쓰지 말고 `.env` 파일로 관리하고, 공유 저장소에 올리지 않습니다.
- 데이터를 받으면 **수집일, 출처 URL, 기준 연도**를 꼭 기록해 두세요 (보고서 4.1에 필요).

## 9. 분석할 때 기억할 점

- **상관 ≠ 인과**: 결론은 "의사 수가 많은 지역은 사망률이 낮은 **경향**이 있다"처럼 연관성으로 표현합니다.
- **역인과 가능성**: 의사가 사망률을 낮추는 게 아니라, 원래 고령·저소득 지역에 의사가 가지 않는 것일 수도 있습니다.
- **생태학적 오류**: 지역 단위 결과를 개인에게 그대로 적용하지 않습니다.
- **표본이 약 230개뿐**: 변수를 너무 많이 넣으면 과적합됩니다. 소득과 의사 수의 다중공선성은 VIF로 확인합니다.
